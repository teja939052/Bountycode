## PART 4 — Parametric Generator Spec

### Core Principle
For quant and pseudocode, the answer is **computable**. The generator changes parameters,
computes the answer with a script (calendar math, fraction math, or interpreter),
and only the stem wording gets human review.

### Template Examples

**T1 — workrate (params: a_days, b_days):**
- Constraint: answer = (a*b)/(a+b), keep integer; a≠b
- Variants: 40+ valid param pairs → 40 verified questions

**T2 — calendar-arith (params: date1, weekday1, offset_days):**
- Script: Python `datetime` computes ground truth → zero hand answers
- Variants: unlimited; constrain to "nice" dates

**T3 — trains-platform (params: train_len, plat_len, speed):**
- Answer = (train+plat)/speed; constrain to integer seconds

**T4 — pseudocode nested-loop-count (params: n, inner start rule):**
- Verified by running interpreter — the player IS the verifier
- Variants: n=2..9, inner = i..n / 1..i / (i*2) rules → 30+ per rule

### Volume Math

| Section | Templates | Variants each | Verified count |
|---|---|---|---|
| Quant (25 templatable patterns) | 25 | ~30 | ~750 |
| Pseudocode (12 archetypes) | 12 | ~20 | ~240 |
| Logical (6 templatable) | 6 | ~25 | ~150 |

## PART 5 — Verification Pipeline

```
generate(params) → script/interpreter computes answer
  → auto-reject if answer ugly (non-integer, ambiguous, negative where impossible)
  → distractor sanity check (no two options equal, no "all of the above")
  → founder reviews stem wording (batch of 20, ~5 min)
  → published: true
```

**Label every item with:** `pattern_id`, `company_relevance` map, `difficulty`, `source: generated-template-v1`, `verified_by: script+founder`.
