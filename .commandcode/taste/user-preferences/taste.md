# User Preferences
- Prefers extending and wiring existing components rather than creating new ones; treats "build another engine" as architectural sprawl to be actively avoided. Confidence: 0.95
- Insists on a single canonical source of truth for shared identities (e.g., skill IDs), with a deterministic mapping layer so all subsystems speak the same language rather than fragmenting taxonomies. Confidence: 0.95
- Wants one server-authoritative state layer; frontend must reflect it, never decide mastery/unlocks from local or client-side flags. Confidence: 0.95
- Opposes duplicating writes unnecessarily; a single normalized longitudinal event log should be the common evidence layer backed by existing domain collections. Confidence: 0.9
- Requires provenance tracking for content (company, source, confidence, year) and never allows fabricated or implied historical provenance (e.g., never labels BountyCode-authored questions as "asked at Amazon"). Confidence: 0.95
- Rejects "synthetic bumps" or localStorage-derived progress; every reported metric must come from authoritative persisted evidence. Confidence: 0.95
- Favors explicit trust/quality tiers for content (e.g., unverified → trusted) over binary "real vs fake" distinctions. Confidence: 0.85
- Prefers evidence-derived, structured diagnosis codes (derived from test patterns, timing, hint usage, answer depth) over simple keyword matching of skill names. Confidence: 0.9
- Provides highly structured, numbered task breakdowns with explicit P0/P1/P2 priority tiers and detailed success criteria; expects tasks decomposed into verifiable, atomic steps. Confidence: 0.9
- Insists on a real-data integration test matrix covering end-to-end state transitions (new user → lesson fail → mastery → OA fail → repair → retest → interview → readiness change → refresh), verifying persisted evidence (mastery_before/after, skill_id, diagnosis, repair, retest, readiness) at every transition. Confidence: 0.9
- Expects performance awareness: bounded queries, indexes, aggregation pipelines, and cached summaries that never override authoritative state. Confidence: 0.85
- Freezes architecture once the core is proven; explicitly stops feature development and only fixes verified bugs, security issues, broken UX, content correctness, and launch blockers. Treats "build more features" as a trap once the engineering core is validated. Confidence: 0.9
- Treats real user payments and behavior as the ultimate validation signal; explicitly rejects more testing as a substitute for market evidence once the core works. Confidence: 0.9
- Wants structured launch checklists for major transitions (development → launch), covering security, infrastructure, data, payments, monitoring, beta-specific validation, and rollback. Confidence: 0.85
- Prefers controlled, small-scale beta launches (e.g., 50–100 users) over big-bang releases; uses existing distribution networks for initial user acquisition. Confidence: 0.85
- Demands forensic reconciliation before accepting any destructive data transformation: every removed record must map to a retained canonical ID with explicit removal reason, no verified/reviewed records may be lost or downgraded, metadata (company/provenance/trust) must survive, distributions must be compared before/after, false positives must be identified, and the derived dataset must not be promoted until reconciliation passes. Confidence: 0.95
- Distinguishes structural assertions (all fields present, schema normalized) from content-quality assertions (pedagogically sound, correctly classified, original, placement-relevant); treats the former as necessary but never sufficient evidence of quality. Confidence: 0.9
- Prefers targeted quality improvements on high-impact items (top N lessons → 90+) over raising averages by adding superficial fields everywhere; explicitly rejects optimizing the mean at the expense of depth where it matters. Confidence: 0.85
- Wants the agent to STOP and produce a forensic audit immediately after any potentially destructive operation, before generating or modifying more content; treats "continue building" as unacceptable until the damage assessment is complete. Confidence: 0.9
